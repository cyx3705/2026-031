2026-028-LocalChat

在微信上跑一条端到端加密的对话通道。

微信在这里只当一条不可信管道：它在服务器上看到的、以及任何人事后翻记录时看到的， 自始至终是密文。真正的明文只在两端的浏览器里存在。

两个部件

部件 是什么 为什么这么做
page/chat.html 单文件网页（当前约 334 KB），发给对方的就是它 加解密全在浏览器里，零安装。它把桥的源码也内嵌进去了
cs/bridge.cs 剪贴板桥，C# / .NET Framework 4.x 用每个 Windows 都自带的 csc.exe 现场编译，用户什么都不用装

桥只做两件事，都靠剪贴板：

  • 发：把密文写进剪贴板 → 把微信切到前台 → Ctrl+V Enter
  • 收：盯着剪贴板，你在微信里 Ctrl+C 就自动推给页面

它不碰微信协议、不碰界面结构，只依赖「剪贴板」和「Ctrl+V」这两个十年不变的东西—— 所以它对微信版本免疫。

快速开始

  1. 把 page/chat.html 发给对方（微信、邮件、U 盘，随便）
  2. 对方用浏览器直接打开这个文件
  3. 双方各点一次右上角 「密钥」，在确认框核对指纹和发送路径后确认 —— 各自的公钥作为一条普通微信消息发出去
  4. 收到对方公钥后自动协商出会话密钥，之后在页面里打字即可

发送目标 = 微信当前窗口中获得焦点的会话，桥不选对话（它读不到微信内部结构）。 所以确认前在微信里切好目标对话；顶栏的「绑定会话」只控制读取，不会改变发送目标。

确认框关闭前不会发送或写入剪贴板。桥在线时确认后走 WebSocket；桥离线或 WebSocket 发送失败时，确认后才复制公钥，并提示手动粘贴。Edge 文件页若拒绝剪贴板权限， 页面会显示错误和可选择复制的公钥文本框。每次真正发送或复制公钥都要重新确认。

「重置密钥」也会先显示当前指纹并确认；确认后旧配对失效、对方公钥清空、输入框重新禁用， 需要重新交换公钥。取消重置会保留当前会话和指纹。

⚠️ 必须用浏览器直接打开文件

如果页面是被塞进某个预览器的沙箱 iframe 打开的（地址栏是 blob:）， 文件选择器和下载都会被安全策略禁掉：

SecurityError: Sandboxed documents aren't allowed to show a file picker.

用 Edge 直接打开 file:///.../chat.html 就没这个限制（实测 showSaveFilePicker 可用）。

装桥时默认点「快速下载」：install-bridge.bat 会出现在 Edge 下载栏，点文件一次即可运行， 不需要再打开资源管理器寻找保存目录；需要指定目录时使用「选择保存位置」。 安装脚本和桥都会检查旧 bridge.exe 进程及 8765 端口，发现旧桥时显示 PID/路径并停止当前启动， 避免覆盖锁定文件或并行启动第二个桥。

加密

环节 用什么
密钥协商 ECDH P-256（WebCrypto 原生，零依赖）
密钥派生 HKDF-SHA256，salt = 双方公钥按字典序拼接
双向分离 派生 64 字节，按公钥字典序切成两把独立的 AES-256 密钥
消息加密 AES-256-GCM，128 位认证标签
nonce 12 字节单调递增计数器，绝不随机
防重放 计数器同时进 AAD；小于等于已见最大值的直接丢弃

消息格式（Base64Url，无 + / =，粘到哪儿都不会被转义）：

公钥交换：  E2E1-K.<base64url(公钥)>
加密消息：  E2E1-M.<base64url(iv || ciphertext || tag)>

为什么 nonce 不用随机的：AES-GCM 在同一把密钥下重用 nonce 会直接泄漏明文和认证密钥。 随机 96 位碰撞概率虽低，但没必要赌；计数器是确定性的，永不重复。

有意没做的（按需求"没那么严谨"）：

  • 没有 SAS 短认证串 → 防不住微信主动做中间人，能防的是被动（存日志、事后翻）
  • 没有前向保密 → 长期身份密钥，私钥泄漏 = 历史消息可解
  • 长度会泄漏 → 密文长度 ≈ 明文长度

详见 DESIGN-E2E.md。

页面里的第三个胶囊：「🧪 测试」——不用等第二个人

点「测试连接」会现场生成第二把真 ECDH 密钥当假对方，走真实的 setPeerPub 协商。 之后你发一条消息，页面会：

  1. 用对方的钥匙真的解开你的出站密文，并校验与原文逐字节一致
  2. 以对方身份加密一条回复
  3. 走正常的入站路径解密显示

微信里于是有一问一答两条密文，页面里有一问一答两条明文——两个方向都真的过了一遍桥。

之所以能这么干：密钥按公钥字典序切成两半，所以 对方的发送键 = 我的接收键。两把钥匙本来就在这台机器上，回路用的是同一套 AES-GCM 和同一套计数器规则，不是模拟。

同一个面板里还有 「📥 反向测试：我当接收方」——模拟对方把公钥发过来 （可以真的发到微信让你 Ctrl+C，也可以直接喂进接收路径）， 让你观察状态切换：清空对方 → 药丸黄、输入框禁用；收下对方的公钥 → 药丸绿、输入框启用。

已知限制

  • ⚠️ 粘贴目标取决于微信内部哪个输入框有焦点。 如果微信没打开任何对话、或焦点停在「搜索」框，密文会粘到奇怪的地方。 桥分辨不了——微信 4.x 主界面是 Qt 自绘，UIA 整个窗口只暴露 1 个元素， 消息文字完全不可读。发送前请确认微信停在对的对话上。
  • 桥是全局单例后端，多个标签页会互相看到消息。
  • 只监听 127.0.0.1，无鉴权：本机自用没问题，暴露到局域网前必须加 token。
  • 公钥不持久化配对：对方公钥只在当前页面会话里有效，刷新后要重新交换。 本机私钥是持久化的，所以你的指纹不变。
  • ✅ 能自动拉取微信里看得见的消息。 面板里点 「📥 拉取最近消息（手动）」， 或者勾上 「收到消息自动拉取」（微信因新消息自己切到前台时桥自动拉一次）： 桥把微信切到前台 → 沿右侧头像列拖一个细长方形（触发微信自己的文字选择）→ Ctrl+C → 读剪贴板。 中文原样显示、密文自动解密，只处理新出现的那些。 只读得到当前对话里看得见的消息。 自动拉取会把光标、前台窗口、剪贴板都还给用户，所以不打断你手上的活。

    走过的弯路：UIA 读不到（Qt 自绘，连开无障碍桥也只有 1 个元素）、 微信没有"全选消息"快捷键（8 种挪焦点的办法全部零变化）、 OCR 会把 Base64Url 认错导致密文解不开。 最后是鼠标拖拽这条微信自己的交互打通的。 另外拖的必须是细长方形：拖一条零宽度的竖线微信什么也不选， 而失败是静默的 —— 会读到上一次留在剪贴板里的旧内容。 详见 page/README.md、cs/README.md。

  • 微信个人号自动化违反微信用户协议，存在封号风险。
