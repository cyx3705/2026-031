HistoryStrenua

PowerSW：SolidWorks 扩展 MCP 指令集，让 AI 和人一起直接操作正在用的那个 SolidWorks

定位

HistoryStrenua 是 HistoryVulcan 的宿主模块，指令域 strenua，面向用户的名字叫 PowerSW。 它附着到用户正在用的 SolidWorks，把建模、装配、标准件选型、出图、标注、公差、检查做成一组粒度清楚的宿主指令：

  • 给 AI：每条指令都经宿主投影成 MCP 工具，AI 可以从零建零件、摆总装、插外购件，再出图、逐个修标注、自检验收； 回执带文字、数据和「本步改了什么」的图纸 SVG，AI 读文字就能核对。原 SolidWorks MCP 已弃用（连旋转零部件都做不到），缺的能力都补在这里（1.38.0）。
  • 给人：常用的出图、标注、检查同时是 Aurora 页面「PowerSW」上的按钮，一下点击代替一串手工操作；控制台里也能直接敲。
  • 边界：只附着，不启动、不隐藏、不退出 SolidWorks；除「新建零件」与点名的 doc.save 外不替用户保存。 批量转换、离线处理文件归 HistoryMinerva（2026-024），不在这里。

AI 怎么用

  1. 查说明书：diana.docs.catalog → diana.docs.read domain=strenua。参数、例子、回执字段都在注册自描述里（宿主 6.1.0 起没有消费文档），本 README 只列指令做什么。
  2. 先看后改：出图前 model.info / asm.list 读模型；改图前 check.svg（图纸读成带编号的 SVG）、view.list、dim.list 拿到视图名、注解名和边 / 孔编号，再按编号寻址修改。
  3. 大粒度起稿，细粒度修：onekey.* 出初稿（回执末尾带本类修正要点，必须照着修完）→ dim.*、tol.*、tech.*、view.move 逐处修 → check.* 验收。
  4. 长指令：经 MCP 调用最多 40 秒先回「还在执行」，指令接着跑；用 strenua.quick.last 取完整回执（完成即返回，最多等 40 秒）。
  5. 笔记：经 MCP 的每条回执最上面带通用区与本类区的注意点；发现指令本身的坑用 note.write 记下（每条 ≤ 100 字，不记项目内容）。

所有指令共用一个执行器：在附着 SolidWorks 的 STA 线程上一次只跑一条（它们共用同一个选择集），可用 strenua.quick.cancel 取消。 写进尺寸、孔标注、技术要求的 Ø ↧ ⌴ ± ° 等符号自动换成 SolidWorks 符号码，不会乱码。

开发与发布

改动只进 vulcan.dev.start 创建的工作区，经宿主 Console CLI 走 vulcan.dev.start → vulcan.dev.submit（候选构建并热装送审）→ vulcan.dev.finish（批准后并回并写入 z-Publish）。 本仓不自行发布；eng/Build-HistoryStrenuaPackage.ps1 只用于本地候选构建。submit 前 diana.docs.audit domain=strenua 须零缺陷。

加一条指令：在 Commands/<类>/ 写一个 QuickCommand（在已附着 SolidWorks 的 STA 线程上执行），登记进 QuickCommands.All； 指令注册、MCP 自描述、按钮、类面板和动作都由登记表生成。只给 AI 的指令不设页面类即可；新类在 QuickCommands 的类名表里登记中文名，页面自动多一块面板。

要点

  • SolidWorks Interop 不在编译期引用，运行时从本机安装目录加载；没装 SolidWorks 的机器照样能构建和跑测试。
  • 一次只跑一条指令：它们共用同一个 SolidWorks 的选择集。
  • 坐标一律图纸 mm、左下角为原点，与 SVG、截图对得上；视图与注解按名字寻址，几何按 SVG 编号寻址。
  • 页面 owner 由指令域推出（strenua → HistoryStrenua），合同检查守着这条。
